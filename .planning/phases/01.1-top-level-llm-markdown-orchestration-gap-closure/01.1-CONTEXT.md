# Phase 01.1: Top-level LLM Markdown Orchestration Gap Closure - Context

**Gathered:** 2026-02-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Close the orchestration-design gap by implementing a markdown-driven skill
runtime where the top-level retrieval skill remains the active orchestrator
throughout the entire query lifecycle and controls all sub-skill spawning.

This phase is focused on runtime orchestration semantics, not on adding new
query decomposition heuristics for coq/split parity.

</domain>

<decisions>
## Implementation Decisions

### Top-level orchestrator lifecycle
- Top-level skill starts first for every query and remains active until final
  response is produced.
- Top-level skill keeps full global state for all spawned sub-skill/sub-agent
  runs and their outputs.
- Top-level skill makes all final sufficiency/continuation decisions.

### Control flow source of truth
- Routing and branch decisions should come from LLM behavior guided by markdown
  skill rules, not hardcoded Python branch logic.
- Top-level markdown and LLM define when to spawn sub-skills, do direct memory
  search, or return final output.
- Sub-skill selection and chaining are decided by top-level LLM.

### Direct search and sub-skill capabilities
- Top-level skill may directly call MemMachine memory search without spawning
  sub-skills.
- Spawned sub-skills must also be able to call MemMachine memory search.
- Sub-skill outputs must be returned to top-level and merged into orchestrator
  state.

### Runtime safety boundaries
- Python runtime may enforce technical guardrails (timeouts/max turns/tool-call
  caps), but must not encode product branching policy.
- Guardrail failures must surface explicit fallback reasons.

</decisions>

<specifics>
## Specific Ideas

- Use markdown skill specs as prompt + policy contracts for top-level and
  sub-skills.
- Expose a constrained tool surface where top-level can spawn sub-skills and
  call direct memory search.
- Keep trace/event logs internal in Phase 01.1 while preserving structured
  state for later observability phases.

</specifics>

<deferred>
## Deferred Ideas

- Accuracy tuning and route-heuristic optimization.
- Rich external trace surfacing/API exposure.
- Coq/split capability parity work beyond orchestration contract.

</deferred>
