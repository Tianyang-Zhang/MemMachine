# Phase 02.2: Single Top-Level LLM Call Integration - Context

**Gathered:** 2026-02-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Refactor retrieval-skill runtime integration to enforce the query-level contract:
Python initiates exactly one top-level LLM session invocation per query, and all
follow-up tool result exchanges happen within that same live session chain.

This phase focuses on orchestration integration semantics and invariant
enforcement, not on new retrieval capability families.

</domain>

<decisions>
## Implementation Decisions

### Query-level call contract
- For each retrieval query, Python should call the top-level LLM runtime once.
- That top-level runtime call must receive top-level markdown policy + tool
  function schemas.
- If model requests tool execution, runtime executes tools and returns tool
  outputs to the still-active session chain.

### Allowed nested model usage
- Tool functions may invoke additional LLM calls when required (for sub-skills
  or helper tasks).
- These nested calls do not violate the single top-level-call contract.

### Runtime authority boundary
- Top-level LLM remains decision authority for next action.
- Python runtime must execute tools/guardrails only and avoid hardcoded product
  branch logic.

### Safety and observability
- Preserve fallback behavior from SAFE requirements for exceptions/timeouts and
  bounded execution.
- Add explicit metrics/assertable state proving top-level was invoked once per
  query.

### Claude's Discretion
- Exact naming/location of the top-level invocation counter/metric.
- Internal wiring details for dependency injection of the new session runtime.

</decisions>

<specifics>
## Specific Ideas

- Add a dedicated top-level orchestration adapter method in `RetrieveSkill`
  that calls `run_live_session(...)` exactly once.
- Route all top-level tools (`spawn_sub_skill`, `direct_memory_search`,
  `return_final`) through runtime handlers executed inside that session.
- Add integration tests that fail if top-level model invocation count exceeds 1
  for a single query.

</specifics>

<deferred>
## Deferred Ideas

- Provider-agnostic single-call abstractions.
- Parallel tool-call execution optimization.
- Any phase-3 decomposition scope expansion.

</deferred>
