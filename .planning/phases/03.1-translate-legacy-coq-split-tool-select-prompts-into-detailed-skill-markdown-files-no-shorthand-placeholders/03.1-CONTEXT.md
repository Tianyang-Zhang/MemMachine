# Phase 3.1: Prompt-to-Markdown Parity Hardening - Context

**Gathered:** 2026-02-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Translate legacy prompt constants into detailed markdown skill specs with
near-literal behavioral parity:
- `TOOL_SELECT_PROMPT` -> `tool_select.md`
- `COMBINED_SUFFICIENCY_AND_REWRITE_PROMPT` -> `coq.md`
- `SPLIT_QUERY_PROMPT` -> `split.md`

This phase hardens markdown policy fidelity and contract strictness.
It does not redesign orchestration runtime flow implemented in earlier phases.

</domain>

<decisions>
## Implementation Decisions

### Parity Depth and Wording (Locked)
- Preserve legacy policy behavior with near-literal parity.
- Preserve original wording as much as possible.
- Resolve ambiguities deterministically in markdown rules (no vague guidance).
- Preserve all legacy constraints, tie-breakers, and bans exactly.

### Markdown Structure and Mapping (Locked)
- Use one fixed section order across all three sub-skill markdown files.
- Maintain one-to-one mapping from legacy prompt blocks into markdown sections.
- Include a dedicated `## Examples` section in each translated markdown file.
- Remove shorthand placeholders; translation must be the source policy.

### Output Contract Policy (Locked)
- Output format aligns with the new skill workflow design (not legacy raw output
  text shape).
- Output contract body is the source of truth for runtime parsing.
- Define strict schema semantics explicitly: required keys, types, enums, and
  fail-closed behavior.
- Keep explicit `v1` contract clauses in each skill markdown.

### Examples, Edge Cases, and Fallback Guidance (Locked)
- Keep legacy examples where still valid.
- Add workflow-aligned examples for the new skill runtime contract.
- Carry all explicit edge cases from legacy prompts.
- Include tie-breaker and fallback demonstrations in examples.
- Target medium example density: 3-5 concrete examples per skill file.

### Claude's Discretion
- Exact heading names under the fixed section order, as long as one-to-one
  prompt mapping and strict output contract requirements are preserved.
- Exact wording for non-functional explanatory prose outside locked rules.

</decisions>

<specifics>
## Specific Ideas

- Add a translation matrix in research/planning docs that maps each legacy
  prompt block to markdown sections for deterministic completeness review.
- Introduce regression tests that fail if placeholders reappear or if critical
  legacy constraints disappear.
- Keep examples short and operational so the model can follow rules quickly
  without diluting strictness.

</specifics>

<deferred>
## Deferred Ideas

- Remove legacy Python prompt constants entirely (separate cutover work).
- Optimize prompt length/token footprint after parity baseline is complete.

</deferred>
