# Requirements: Skill-Orchestrated Retrieval Agent

**Defined:** 2026-02-27
**Core Value:** Every query is handled by the right retrieval workflow, with reliable fallback to direct memory search when confidence is low or execution is unstable.

## v1 Requirements

### Orchestration

- [x] **ORCH-01**: Developer can execute retrieval through a top-level `retrieve-skill` orchestrator for each query.
- [x] **ORCH-02**: Developer can run multiple sub-skills in one retrieval flow and receive one normalized final result.
- [x] **ORCH-03**: Developer can inspect route and execution trace metadata for each retrieval request.

### Routing and Decomposition

- [x] **ROUT-01**: Developer can route each query through `select-skill` with an explicit confidence signal.
- [x] **ROUT-02**: Developer can execute multi-hop decomposition via `coq-skill` and receive normalized output.
- [x] **ROUT-03**: Developer can execute branch decomposition via `split-skill` and aggregate branch results.
- [x] **ROUT-04**: Developer can route split branches through `coq-skill` when branch queries are multi-hop.

### Fallback and Reliability

- [x] **SAFE-01**: System falls back to direct MemMachine search when any sub-skill returns low confidence.
- [x] **SAFE-02**: System falls back to direct MemMachine search when a sub-skill fails with an exception.
- [x] **SAFE-03**: System falls back to direct MemMachine search when a sub-skill exceeds timeout budget.
- [x] **SAFE-04**: System enforces bounded execution (max hops/branches/steps) to prevent unbounded loops.

### Migration and Validation

- [x] **MIGR-01**: Legacy retrieval-agent execution path is removed after skill path is wired end-to-end.
- [x] **MIGR-02**: Existing retrieval API response shape remains compatible after migration.
- [x] **MIGR-03**: Developer can run first 100 WikiMultiHop queries end-to-end as a functionality gate.
- [x] **MIGR-04**: Retrieval runtime terminology is skill-first (`skill`,
  `skill_name`, skill labels) and no active retrieval path depends on legacy
  `agent` naming.

## v2 Requirements

### Optimization and Expansion

- **OPT-01**: Developer can tune prompts and policies for accuracy improvements post-migration.
- **OPT-02**: Developer can add new skills beyond `select/coq/split/fallback` with formal onboarding checks.
- **OPT-03**: Developer can compare alternative skill policies using repeatable evaluation baselines.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Accuracy optimization campaign in this milestone | Milestone focus is functional migration and safety first |
| New skill families beyond initial four | Keep migration risk bounded |
| Long-lived dual execution mode | Adds maintenance cost and behavioral drift |
