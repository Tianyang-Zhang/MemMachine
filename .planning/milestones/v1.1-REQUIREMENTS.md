## v1.1 Requirements (Final)

### Sufficiency Signals

- [x] **SUFF-01**: `coq`, `split`, and top-level each produce
  `is_sufficient` and confidence outputs for logging/debug artifacts.
- [x] **SUFF-02**: Parent skills compute sufficiency from retrieved
  episodes/context and do not depend on child `is_sufficient` outputs for
  control.
- [x] **SUFF-03**: For insufficient states, skills can report related evidence
  candidates and confidence markers in output contracts.

### Filtering Workflow

- [x] **FILT-01**: Skills support LLM-led episode review before deciding next
  action.
- [x] **FILT-02**: Insufficient-path rule: if any related episode confidence is
  `>= 0.7`, low-confidence episodes are deprioritized for next-step reasoning;
  if none reach threshold, keep all episodes.
- [x] **FILT-03**: Sufficient-path rule: for high-confidence decisions, evidence
  selection can be emitted; if selection is empty, fallback behavior keeps all
  episodes.

### Split Live Verification

- [x] **SPLT-01**: `split` runs one live verification pass after branch
  execution using accumulated branch context.
- [x] **SPLT-02**: Split verification pass may rerun branches when verification
  detects missing evidence/noise.
- [x] **CONT-01**: Upper-level skill receives lower-level return context
  (episodes + structured outputs) for verification/filter decisions.

### Metrics and Validation

- [x] **METR-01**: Top-level sufficiency signals are exposed in perf metrics and
  trace outputs similarly to sub-skill sufficiency signals.
- [x] **BENCH-01**: Team can execute
  `./run_test.sh wikimultihop optv2 search retrieval_skill 100` and capture
  benchmark output artifacts.
